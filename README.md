# delivery-planner

Планировщик доставок курьера на день: список доставок, свой порядок объезда и документы, которые нужно распечатать к доставке.

Проект в разработке: логика есть, вёрстки пока почти нет.

## Что уже работает

### Список доставок

- Доставки на сегодня. Данные пока статичные — `src/meetings.ts`.
- Порядок меняется перетаскиванием — мышью и пальцем (dnd-kit). Под курсором едет копия карточки.
- Срочные доставки всегда наверху.
- «Скрыть завершённые»: двигаются только видимые карточки, скрытые остаются на своих местах.
- Новый порядок отправляется на сервер. Пока это имитация в коде (`saveDeliveryPosition`): ответ через 0,5 с, каждый третий запрос падает. При ошибке порядок откатывается. Пока запрос идёт, перетаскивать нельзя.
- Порядок, который принял сервер, хранится в браузере (localStorage) до конца дня.

### Документы к доставке

У части доставок есть документы (`documentId`) — их нужно подготовить и распечатать.

- При запуске приложение одним запросом отправляет на подготовку документы всех доставок.
- На карточке — кнопка со статусом: «Подготовка документов», «Печать не требуется», «Ошибка печати», «Напечатать документы».
- Пока документ готовится, статус запрашивается каждые 3 секунды. Когда документ готов, опрос останавливается.
- Если подготовка упала (статус `error` или `deleted`), документ сам уходит на подготовку ещё раз.
- «Напечатать документы» открывает документ в новой вкладке, вкладка сама вызывает печать.

### Фейковый сервер

Своего бэкенда пока нет. В режиме разработки запросы к `/api` перехватывает MSW (`src/mocks/`).

- `POST /api/documents/prepare` — тело `{ ids }`, ответ `{ errors: [{ id, message }] }`
- `GET /api/documents/:id/status` — ответ `{ id, status }`
- `GET /api/documents/:id/file` — HTML-страница документа

Как ведёт себя сервер:

- статус считается по времени с момента подготовки: `new` (0–3 с) → `processing` (3–6 с) → `queued` (6–9 с) → `ready`;
- `doc-103` — «Документы уже выданы», сервер его не готовит;
- `doc-102` и `doc-104` при первой подготовке падают (`error` и `deleted`), после повторной готовятся как обычно.

Проверить ошибки — в консоли браузера, потом F5:

```js
localStorage.setItem("failPrepare", "1"); // общий запрос подготовки отвечает 500
localStorage.setItem("failRestart", "1"); // 500 только при повторной подготовке
localStorage.removeItem("failPrepare"); // вернуть как было
```

### Проверки (CI)

На каждый PR и push в `main` GitHub Actions запускает Prettier, ESLint и сборку. Прямой push в `main` запрещён — изменения только через PR.

## Чего пока нет

- Вёрстки — стили минимальные.
- Маршрутов: полная карточка доставки (`DeliveryCardFull`) — заготовка, не подключена.
- Своего бэкенда. MSW работает только в режиме разработки, в сборку не попадает.
- Тестов.

## Стек

React 19, TypeScript, Vite 8, Redux Toolkit + RTK Query, dnd-kit, MSW, ESLint, Prettier, GitHub Actions.

## Запуск

Нужен Node.js 24 — как в CI.

```bash
npm ci
npm run dev
```

## Скрипты

| Команда                | Что делает                                 |
| ---------------------- | ------------------------------------------ |
| `npm run dev`          | dev-сервер, с фейковым сервером MSW        |
| `npm run build`        | проверка типов и сборка в `dist/`          |
| `npm run preview`      | открыть собранную версию                   |
| `npm run lint`         | ESLint                                     |
| `npm run format`       | Prettier: исправить форматирование         |
| `npm run format:check` | Prettier: только проверить — так делает CI |

Перед push: `npm run format`, `npm run lint`, `npm run build`.

## Структура `src/`

```text
src/
├── app/          store, базовый API (rootService) и API документов
├── components/   список, карточки, перетаскивание, кнопка печати
├── hooks/        usePrepareDocuments — общий запрос подготовки при запуске
├── mocks/        фейковый сервер MSW
├── utils/        порядок карточек, localStorage, печать
├── meetings.ts   данные доставок
└── types.ts      тип Delivery
```
